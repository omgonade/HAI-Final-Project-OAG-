## Project Overview

This project analyzes the UCI Adult Census Income dataset for bias and fairness issues,
trains a baseline classifier, and applies three mitigation strategies to reduce unfairness
across sex groups.

### Key Objectives
1. Load and preprocess the Adult Census dataset
2. Conduct a pre-training bias audit (sampling, historical, measurement, proxy bias)
3. Train a baseline model and evaluate overall + subgroup performance
4. Compute fairness metrics (statistical parity, disparate impact, equalized odds)
5. Apply three mitigation strategies:
   - Feature elimination
   - Reweighting
   - Threshold optimization
6. Compare results before/after mitigation

## Dataset: UCI Adult Census Income

**Source**: [UCI ML Repository - Adult Dataset](https://archive.ics.uci.edu/ml/datasets/adult)

**Size**: 48,842 rows total (32,561 train + 16,281 test, combined and de-duplicated of
missing values by `load_data()`)

**Features**:
- **Demographic**: age, sex, race, native-country
- **Occupation**: workclass, occupation, education, education-num
- **Financial**: capital-gain, capital-loss
- **Social**: marital-status, relationship
- **Target**: income (>50K or ≤50K)

**Notable issues** (see full audit output for numbers):
- Imbalanced target (~76% earn ≤50K)
- Skewed demographics: ~2:1 male-to-female, ~85% White
- Historical bias: income labels reflect 1994 labor-market wage gaps by sex/race

## What's in `pipeline.py`

| Function | Purpose |
|---|---|
| `load_data()` | Reads `adult.data` + `adult.test`, combines them, drops missing rows, builds binary income label |
| `preprocess(df, drop_proxies=False)` | Label-encodes categoricals; `drop_proxies=True` removes sex/relationship/marital-status (feature elimination) |
| `bias_audit(df)` | Prints representation and income-rate breakdowns by sex/race, plus a proxy check (relationship vs. sex) |
| `train_and_evaluate(...)` | Splits data, scales features, trains a model, evaluates it |
| `evaluate_predictions(...)` | Computes accuracy/precision/recall/F1, subgroup metrics, and DP Diff / DP Ratio / EO Diff |
| `mitigate_reweighting(X, y, s)` | Returns per-sample weights that upweight underrepresented (sex, income) combinations |
| `mitigate_threshold_optimizer(...)` | Wraps `fairlearn.postprocessing.ThresholdOptimizer` to pick group-specific decision thresholds |

Fairness metrics used:
- **Statistical Parity Difference (DP Diff)** — gap in selection rate between sex groups (0 = fair)
- **Disparate Impact Ratio (DP Ratio)** — selection-rate ratio (1.0 = fair; <0.8 fails the legal "80% rule")
- **Equalized Odds Difference (EO Diff)** — gap in true-positive rate between sex groups (0 = fair)

## Actual Results

From a real run of `python pipeline.py` (see `output/summary_results.csv`):

| Model | Accuracy | F1 | DP Diff | DP Ratio | EO Diff |
|-------|----------|------|---------|----------|---------|
| Baseline | 0.8248 | 0.5519 | 0.1727 | 0.1734 | 0.2591 |
| Feature Elimination | 0.8134 | 0.5029 | 0.0773 | 0.5223 | 0.0229 |
| Reweighting | 0.7434 | 0.5693 | 0.1020 | 0.7388 | 0.0547 |
| Threshold Optimization | 0.8048 | 0.4695 | 0.0577 | 0.6100 | 0.0041 |

**Key findings:**
- Baseline is badly unfair: DP Ratio of 0.173 is far below the legal 80% threshold.
- Feature Elimination gives the best fairness-per-accuracy trade-off (~1pp accuracy cost,
  DP Diff down 55%, EO Diff down 91%).
- Reweighting achieves the best DP Ratio (0.739) but at the largest accuracy cost (~8pp).
- Threshold Optimization nearly eliminates the equalized-odds gap (0.004) by design, at
  the cost of F1.

Numbers will vary slightly if you re-run the pipeline unless `RANDOM_STATE = 42` is kept
fixed (it is, by default).

## Bias Sources Identified in the Adult Dataset

1. **Sampling bias** — 1994 US Census extract, ~67% male, ~85% White; not representative
   of the current population.
2. **Historical/label bias** — the income label itself reflects real 1994 wage gaps
   (men earn >50K at ~3x the rate of women in this data), so the bias is in the ground
   truth, not just the features.
3. **Measurement bias** — features like `hours-per-week` differ systematically by sex
   (42.4 hrs/week for men vs. 36.4 for women), encoding historical labor patterns.
4. **Proxy bias** — `relationship` almost perfectly encodes sex (60% of men are recorded
   "Husband", 14% of women "Wife"), so dropping `sex` alone doesn't remove the signal.

Full numeric breakdown is printed by `bias_audit()` when you run `pipeline.py`.
